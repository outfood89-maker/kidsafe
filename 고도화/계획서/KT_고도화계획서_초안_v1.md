## 요약

Kiddy 는 아이의 첫 미디어 경험 공간입니다. 키디가 기분을 묻고, 아이가 답하고,
부모는 아이가 공유하기로 한 것만 받아 봅니다.

**12주의 목표는 두 가지입니다.**
① 설계·검증까지 마치고 발부 대기 중인 **기능 브리프 백로그를 소화**해 사용자 경험을 완결하고
② 그 결과를 **"오늘 실제 가정에 배포해도 되는 완성도"** 로 증명합니다(4개 관문).
배포 자체는 이번 범위가 아니며, 확장(교육 플랫폼·TV·보육기관)은 설계서까지 완성합니다.

## 1. 앱의 현재 상태

### 1-1. 한 줄 정의

'영상 검수 도구'가 아니라 **아이의 첫 미디어 경험 공간** — 아이가 발화 주체인 가족 왕복 루프
(아이가 말하고 → 부모가 답하고 → 키디가 목소리로 배달)를 3단 AI 검수 파이프라인이 안전하게 받칩니다.

## 3. 고도화 방향 및 기술적 검토

### 3-1. 방향 — 설계 완료된 브리프 백로그의 소화

저희는 기능마다 **작업지시서(브리프)** 를 먼저 쓰고 구현하는 체계로 개발해 왔습니다
(브리프 계보 40여 장 · 각 브리프는 전제→구현→검증→아동 문구 검수 4단 구성).
공모전 마감으로 **설계·검증까지 끝났으나 착수하지 못한 브리프**가 쌓여 있으며,
이번 고도화는 새 기능의 발명이 아니라 **이 백로그 중 핵심을 완결하는 것**입니다.

**핵심 브리프 후보** (★=핵심 제안 · [ ] 오너 확정 대기)

| 기 | 브리프 | 무엇 | 왜 핵심인가 |
|---|---|---|---|
| 1기 | ★ 완벽하지 않은 키디 (GD-38 잔여) | 실패를 아이 탓으로 돌리지 않는 문구·연출 전면 적용 | 아동 정서 원칙의 완결 — 부분 적용 상태 |
| 1기 | ★ 아동 안내 화면 (B3) | 글 못 읽는 아이를 위한 시각·음성 안내 | 한계 #3 직결 |
| 1기 | ★ "키디가 걸러낸 영상" 가시성 카드 | 검수가 일하고 있음을 부모가 보게 | 검수 신뢰의 가시화 — 부모 축 로드맵 1순위 |
| 1기 | 폴백·안내 완결 (리포트 502 · YouTube 쿼터 안내 등) | 외부 장애 시 아이가 "조용한 화면"을 보지 않게 | 한계 #4 |
| 2기 | ★ 위기 감지 근본 개선 (GD-37) | 금지어 목록 → 공개 표준(아동권리보장원 매뉴얼 등) 기반 재설계 + 대응 절차, 판단마다 출처 명시 | 한계 #1·#2 — 안전의 심장 |
| 2기 | ★ 개인정보 체계 완결 (B1 + 법정대리인 동의) | 처리방침 완성(조항마다 코드 동작 대조) · 동의 체계 구현 | 한계 #8 — 아동 서비스의 기본기 |
| 2기 | ★ 가족 앨범 1단계 — 내려받기 (GD-39 최소 조각) | 선택분 ZIP/PDF 내려받기 | "정리하세요"가 "아이 그림을 버리세요"가 되지 않게 |
| 3기 | ★ '작년 오늘' 타임캡슐 | 아이의 예전 목소리·그림이 1년 뒤 도착 | 기존 데이터 재사용이라 비용 최소·정서 가치 최대 |
| 3기 | 가족 왕복 우체국 1~2건 (질문 릴레이 · "같이 보고 싶어" 예약) | 아이→부모 방향의 왕복 강화 | 작품설명서 1개월차 약속 |
| 3기 | 실기기 검증 + 완성도 관문 통과 기록 | 핵심 여정(체크인→시청→일기→리포트)을 iOS·Android 실기기에서 | 한계 #6 |

### 3-2. "다 됐다"의 기준 — 완성도 4관문

| 관문 | 통과 기준 |
|---|---|
| 🚨 안전 | 위기 감지·대응이 공개 표준 기반으로 재설계 + 판단마다 출처 명시 + 정탐/오탐 측정치 |
| ⚖️ 법 | 처리방침이 개인정보보호위 공개 지침 기반으로 완성, **조항마다 실제 코드 동작과 대조** |
| ✅ 품질 | 자동 검증(서버 11종·프론트 401건) 전부 통과 유지 · 신규 기능마다 검증 코드 동반 |
| 📱 기기 | 실기기에서 핵심 사용자 여정 정상 동작 |

외부 검증(아동심리 전문가 검수·법률 검토)은 **실사용 노출 전 관문**으로 배치하고
본 기간은 공개 1차 자료 기반으로 내부 완결합니다(본 예산 범위 외).

### 3-3. 기술적 검토

- **브리프 체계 유지**: 모든 항목은 전제(권한 등급·예상 용량/비용 명시) → 구현 → 자동 검증 → 아동 문구 사람 검수의 4단을 거침
- **위기 감지(2기)의 기술 방침**: LLM 판정 배제 유지(오판·재해석 위험) — 사람이 검수한 사전과 고정 응답 확장 방식.
  분류 축은 공개 표준에서, 문장은 공개 사례 자료에서, 검증은 정탐·오탐 양방향 측정으로
- **타임캡슐(3기)의 기술 방침**: 신규 수집 없음 — 이미 저장된 일기·음성의 시간축 재구성이라 개인정보 면적이 늘지 않음

## 4. 확장성 (활동 계획)

### 4-1. 교육 플랫폼으로의 확장

시청·정서 돌봄에서 **아이의 발달을 돕는 교육 경험**으로 넓힙니다. 준비된 설계 자산:
- **감정 단어 사다리** — 나이에 따라 자라는 감정 어휘 (체크인 데이터와 연결)
- **그림책 연동(StoryWeaver 등 오픈 라이선스)** — 시청 대신 '읽어주는 키디'
- **미디어 리터러시** — "어떻게 알았어?" 되묻기 등 대화형 사고 훈련 (연령 한정 설계)
- 이번 기간 산출물: 교육 축 설계서 + 1건 프로토타입 [ ] 범위 오너 확정

### 4-2. TV 이식 (KT 협의 희망 항목)

전략은 **"폰이 컨트롤러, TV가 액자"** — 아이의 창작은 폰에서, TV는 가족이 함께 보는 큰 화면.
2-2의 제약 조사에 따라 **KT 셋톱 + 웹뷰**를 현실 경로로 보며, 셋톱 웹뷰 사양·엔진 버전·
YouTube 재생 정책 등 **KT 확인이 필요한 질문 19문**을 준비해 두었습니다.

### 4-3. 보육기관(어린이집·유치원) 확장
