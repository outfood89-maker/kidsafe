## 요약 — 이번 고도화가 하는 일

Kiddy 는 아이의 첫 미디어 경험 공간입니다. 키디가 기분을 묻고, 아이가 답하고,
부모가 아이가 공유하기로 한 것만 받아 봅니다. 공모전 출품작은 이 경험이 "동작하는" 단계였습니다.

**12주의 목표는 새 기능의 나열이 아니라, "오늘 실제 가정에 배포해도 되는 완성도"입니다.**
배포 자체는 이번 범위가 아니지만, 배포를 막고 있는 것들 — 비용 폭주 방어의 빈 칸,
위기 대응 설계, 저장 인프라 정합, 실기기 검증 — 을 전부 치우고,
그 완성도를 **측정 가능한 5개 관문**으로 증명합니다.

| 구간 | 주제 | 한 줄 |
|---|---|---|
| 1기 (8/26~9/22) | 돈이 새지 않게 | 전역 상한 · 저장 정합 · 검증 장치 완결 |
| 2기 (9/23~10/20) | 아이가 다치지 않게 | 위기 대응 설계 · 처리방침 · 앨범 내려받기 |
| 3기 (10/21~11/20) | 증명 | 실기기 검증 · 5관문 통과 · 신기능 1건 · 확장 설계서 |

## 1. 앱의 현재 상태

### 1-1. 정체성과 구조

'영상 검수 도구'가 아니라 **아이의 첫 미디어 경험 공간**입니다.
아이가 발화 주체인 가족 왕복 루프(아이가 말하고 → 부모가 답하고 → 키디가 배달)가 뼈대이고,
3단 AI 검수 파이프라인이 그 경험을 안전하게 받칩니다.

### 1-2. 화면 구성 (13개 화면 — 전부 구현·배포 상태)

| 축 | 화면 | 기능 |
|---|---|---|
| 공용 | Landing · Login · ProfileSelect · Privacy | 소개 / 가입·로그인(Supabase Auth) / 아이 프로필 선택(최대 4명) / 개인정보 처리방침 |
| 아이 | **KidHome** | 검색·추천·시청 — 검수 버튼 없이 결과 전체가 3단 파이프라인 통과 후 신호등 표시, 숏폼 차단 |
| 아이 | **KiddyRoom** | 키디와 자유 대화(음성 입출력) — 위기 스크리닝이 되읽기·외부 전송보다 먼저 |
| 아이 | 데일리 체크인 | 기분·하루·볼 것 3문항, 이모지·음성 답변, '비밀이야' 는 **저장 자체를 안 함** |
| 아이 | 그림일기 | 말·선택 → 문장 완성 + AI 그림, 아이 낙서 이어 그리기(원본 보존), 음성 메모 |
| 아이 | BadgeCollection · MiniGame · Favorites | 건강한 습관에만 배지 / 미니게임 / 즐겨찾기 |
| 가족 | **FamilyShelf** | 가족 책장 — 일기·도장·편지·음성 편지, 부모 답장을 키디가 낭독 |
| 부모 | **ParentDashboard** | 주간 리포트 · AI 코치 · 시청 분석 · 일정 · 위기 신호(존재만) · 📦 저장 공간 관리 |
| 부모 | Account | 회원 탈퇴 — DB 행 + Storage 실물 파일까지 삭제 (2026-08-10 구현·검증) |
| 운영 | AdminPage | 4중 잠금(로그인→role→비밀번호 재확인→서버 검증) |

### 1-3. 기술 스택과 AI 배치

- 프론트 React 19 + Vite (Vercel) / 백엔드 FastAPI (Railway) / DB·Storage·Auth Supabase
- **역할별 지능 배치**: Claude Haiku=실시간 반응(챗봇·체크인) / Claude Sonnet=주간 리포트·AI 코치 /
  Claude Vision=자막·썸네일 7축 정밀 검수 / GPT Image=그림일기(경량)·이어그리기(상위, 원본 보존 설정) /
  CLOVA Voice=키디 목소리 / Web Speech=아이 말 듣기
- **원칙 "사실은 코드가, 말투만 AI가"**: 감정 집계·점수·위기 판정에 LLM 미사용 —
  위기 감지는 사람이 검수한 사전(辭典)과 고정 응답만 (오판·재해석 원천 차단)

### 1-4. 기능 정의의 정본 — 문서가 아니라 검증 코드

기능 정의서를 별도 문서로 관리하는 대신, **기능의 계약을 자동 검증 코드로 박제**해 두었습니다.
문서는 낡지만 검증은 커밋마다 돌기 때문입니다.

| 검증 체계 | 규모 |
|---|---|
| 서버 계약 검증 | **11종** — 인증 기준선 · 인가(소유권) · 윤리선 카나리아 · 비용 상한 · 위기 사전 · 저장 계약 · 고아 자산 · 탈퇴(계약+실행) · 저장 용량 · 검증 도구 자체 점검 |
| 프론트 테스트 | **42파일 401건** (vitest) |
| API 전수 판정 | **엔드포인트 83개** 전건 권한 등급 판정 완료 |
| 커밋 훅 | 위 전부 + 성능 회귀(배럴 import) 차단 — 검증 실패 시 커밋 자체가 막힘 |

### 1-5. 출품 이후 변경 고지 (작품설명서와의 차이)

작품설명서에는 그림일기·음성이 *"가족의 기기에 저장하는 것을 원칙"* 으로 기재돼 있습니다.
출품 이후 **서버 저장으로 전환**했습니다 (2026-08-09). 이유와 안전장치:

- **이유**: 기기를 바꾸면 아이의 그림·목소리가 사라짐 — "기록이 가보가 된다"는 약속과 충돌
- **안전장치**: 이중 게이트(전역 킬스위치 ∧ 보호자 명시 동의) · 부모 화면에는 아이가 공유 선택한 것만 ·
  탈퇴 시 Storage 실물 파일까지 삭제(검증 코드로 박제) · 계정별 저장 용량 상한

## 3. 고도화 방향 및 기술적 검토

### 3-1. 원칙 — "완성도를 측정 가능하게"

배포는 이번 범위가 아니므로, **"다 됐다"의 기준을 5개 관문으로 정의**하고 전부 통과시키는 것을
목표로 합니다. 관문마다 통과 증거(숫자·기록)를 남깁니다.

| 관문 | 통과 기준 |
|---|---|
| 💸 비용 | 부하 시험에서 전역 상한이 실제로 차단 — 최악 시나리오 일일 노출액을 숫자로 제시 |
| 🚨 안전 | 위기 감지·대응이 공개 표준 기반으로 재설계되고 판단마다 출처 명시 · 정탐/오탐 측정치 공개 |
| ⚖️ 법 | 개인정보 처리방침이 개인정보보호위원회 공개 지침·표준안 기반으로 완성, 조항마다 실제 코드 동작과 대조 |
| ✅ 품질 | 자동 검증(서버 11종+프론트 401건) 전부 통과 유지 + 신규 기능마다 검증 코드 동반 |
| 📱 기기 | 실기기(iOS·Android)에서 핵심 여정(체크인→시청→일기→부모 리포트) 정상 동작 |

**외부 검증(아동심리 전문가 검수 · 법률 검토)은 실사용 노출 전 관문으로 배치**하고
본 기간에는 공개 1차 자료 기반으로 내부 완결합니다 — 본 고도화 예산 범위 외입니다.

### 3-2. 12주 로드맵

**1기 — 돈이 새지 않게 (8/26 ~ 9/22)**
- 사용량 카운터 DB 영속화 → **전역 일일 상한** (한계 #1)
- 저장 용량을 아이별 상한으로 재설계 + 인프라 상한과 정합 (한계 #4)
- 검증 장치의 빈 칸 보수(자체 정밀검수에서 발견한 항목들) — "검사가 검사를 통과하는" 상태 제거

**2기 — 아이가 다치지 않게 (9/23 ~ 10/20)**
- 위기 감지 사전 확장 + 대응 절차 설계 — 공개 표준 기반, 판단마다 출처 표 (한계 #2·#3)
- 개인정보 처리방침 완성 — 조항마다 코드 동작 대조 (관문 ⚖️)
- 앨범 내려받기 (한계 #6) · 글 못 읽는 아이를 위한 안내 개선

**3기 — 증명 (10/21 ~ 11/20)**
- 실기기 검증 (관문 📱) · 5관문 전체 통과 기록
- 신기능 1건: **'작년 오늘' 타임캡슐** — 아이의 예전 목소리·그림이 1년 뒤 도착
  (작품설명서 4-2 약속 항목 중 기존 데이터 재사용이라 비용이 가장 낮고 정서 가치가 가장 큼)
- 확장 설계서 완성 (→ 4장) · 결과 보고서

### 3-3. 기술적 검토 — 왜 이 순서인가

비용→안전→증명 순서는 의존성입니다. 전역 상한 없이 기능을 늘리면 늘어난 만큼 노출액이 커지고,
위기 대응 설계 없이 실기기 검증을 해도 "배포 가능"이라 말할 수 없습니다.
각 기 산출물이 다음 기의 전제가 되도록 배치했습니다.

## 4. 확장성 (활동 계획)

### 4-1. TV — "웹 코어 + 셸" 전략 (KT 협의 희망 항목)

핵심 기능을 전부 웹 코어에 두고, TV 는 얇은 껍데기만 갈아 끼우는 구조로 설계합니다.
**스카이라이프 셋톱 내장 웹 / 안드로이드 앱 래퍼 양 트랙을 모두 준비**하되,
확정은 KT 전문 부서와의 협의로 정합니다 — 웹 코어 우선이면 어느 쪽이 되어도 재작업이 없습니다.

준비된 자산: 스마트TV 7축 조사(64항목·출처 147건) · 셋톱 연동 질문 리스트 19문 ·
TV 고유 제약 검토(리모컨 포커스 내비게이션 · 마이크 부재 시 축소 설계 · 3m 거리 UI).
설계 검증은 Tizen/webOS 공식 에뮬레이터(무료)로 진행합니다.

### 4-2. 기관 — '우리 반 마음 날씨'

유치원·지역아동센터용 **개인 식별 없는 익명 집계** 화면과 선생님 도장.
가정의 왕복 루프를 마을 단위로 확장하는 설계이며, 이번 기간에는 설계서까지 완성합니다.
(기관 종사자는 아동학대 신고의무자이므로, 위기 신호 표시 설계는 그 법적 지위와 함께 검토합니다)

### 4-3. 플랫폼 — 검수 엔진 API (B2B)

검수 엔진은 영상 소스 독립으로 설계돼 있어 유튜브 외 소스 연동과 검수 API 제공이 가능합니다.
비유튜브 콘텐츠 소스 조사(완료)를 바탕으로 연동 우선순위 설계서를 남깁니다.
