## 요약

Kiddy 는 아이의 첫 미디어 경험 공간입니다. 키디(AI 친구)가 기분을 묻고, 아이가 답하고,
부모는 아이가 공유하기로 한 것만 받아 봅니다.

**12주의 목표는 두 가지입니다.**
① 설계와 검증까지 마쳐 두고 공모전 마감으로 착수하지 못한 **기능 작업 목록을 완성**하고
② 그 결과를 **"오늘 실제 가정에 내놓아도 되는 완성도"** 로 증명합니다(4개 통과 기준).
출시 자체는 이번 범위가 아니며, 확장(그림책·TV·보육기관)은 설계서까지 완성합니다.

## 1. 앱의 현재 상태

### 1-1. 한 줄 정의

'영상을 걸러주는 도구'가 아니라 **아이의 첫 미디어 경험 공간** — 아이가 말하고(체크인·그림일기),
부모가 답하고(도장·편지·음성), 키디가 그 답을 목소리로 배달하는 **가족 왕복 구조**를,
AI 영상 검수가 안전하게 받치고 있습니다.

### 1-2. 화면별 기능 (13개 화면 · 전부 구현되어 서비스 중)

> 📎 **부록 A: 화면별 실제 스크린샷** 첨부 예정 (제출본 포함). 아래 표는 그 색인입니다.

| 화면 | 쓰는 사람 | 무엇을 하나 |
|---|---|---|
| 랜딩 · 로그인 | 방문자·보호자 | 서비스 소개 · 이메일 가입과 로그인 |
| 프로필 선택 | 가족 | 아이 프로필 선택·생성 (계정당 최대 4명) |
| **아이 홈** | 아이 | 영상 검색·추천·시청. 별도의 검수 버튼 없이 검색 결과 전체가 3단계 AI 검사(주제어 → 채널 → 자막·썸네일 정밀분석)를 거쳐 신호등(🟢🟡🔴)으로 표시 · 연령에 맞는지 별도 표시 · 짧은 중독성 영상(숏폼) 차단 |
| 데일리 체크인 | 아이 | 키디가 목소리로 기분·하루·보고 싶은 것을 묻고, 아이는 이모지나 말로 답합니다. **'비밀이야'라고 한 답은 저장 자체를 하지 않습니다** |

| 키디의 방 | 아이 | 키디와 자유 대화(음성). 위험 신호가 담긴 말은 AI 에 맡기지 않고 **사람이 미리 검수한 고정 답변**으로만 응답 |
| 배지 · 미니게임 · 즐겨찾기 | 아이 | 건강한 시청 습관에만 배지 부여 · 놀이 요소 |
| **가족 책장** | 가족 | 그림일기를 월별로 함께 열람 · 부모의 도장·편지·음성 편지를 **키디가 아이에게 읽어줌** |
| **부모 대시보드** | 부모 | 주간 리포트 · AI 육아 코치 · 시청 분석 · 저녁 대화 소재("대화의 씨앗") · 위기 신호 알림(**내용 없이 존재만**) · 저장 공간 관리 |
| 계정 관리 | 부모 | 회원 탈퇴 — 기록뿐 아니라 서버에 저장된 그림·음성 파일까지 함께 삭제 |
| 처리방침 · 관리자 | 공용·운영 | 개인정보 처리방침 · 관리자 화면(4중 잠금) |

### 1-3. 기술 구성

- **화면**: React (Vercel 에서 서비스) / **서버**: FastAPI (Railway) / **데이터 보관**: Supabase
- **AI 역할 분담**: 실시간 반응은 빠르고 저렴한 모델(Claude Haiku), 주간 리포트·코치는 상위 모델(Claude Sonnet),
  영상 정밀검수는 화면을 읽는 모델(Claude Vision), 그림 생성은 GPT Image, 키디 목소리는 CLOVA Voice
- **원칙 "사실은 코드가, 말투만 AI가"** — 감정 집계·점수·위기 판정 같은 '사실'에는 AI 를 쓰지 않습니다.
  AI 가 지어내거나 왜곡할 수 있는 자리에는 사람이 검수한 고정 문구만 씁니다
- **품질 장치**: 코드를 반영할 때마다 자동 검사(서버 계약 검사 11종 + 화면 테스트 401건)가 돌고,
  하나라도 실패하면 **반영 자체가 막힙니다**

## 3. 고도화 방향 및 기술적 검토

### 3-1. 방향 — 설계를 마친 작업 목록의 완성

저희는 기능마다 **작업지시서**를 먼저 쓰고 구현하는 방식으로 개발해 왔습니다
(전제 → 구현 → 자동 검증 → 아동 문구 사람 검수의 4단 구성, 누적 40여 건).
이번 고도화는 새 아이디어의 발명이 아니라, **설계·검증까지 끝났으나 공모전 마감으로
착수하지 못한 작업 중 핵심을 완성하는 것**입니다.

**핵심 작업** (★ = 확정 항목)

| 기 | 작업 | 무엇 |
|---|---|---|
| 1기 | ★ **아동 안내 화면** | 글 못 읽는 4~7세를 위한 시각·음성 안내 — 오류·대기가 "조용한 화면"이 되지 않게 (한계 #3) |
| 1기 | ★ **대화 레시피** — 연령·일기 기반 양육 가이드 | 아이의 **나이(발달 시기)와 그림일기 속 실제 사건·감정**을 재료로 "오늘 저녁 아이에게 건넬 한마디"를 부모에게 주 1회 제안.<br>안전 레일: 재료는 아이가 가족과 공유한 것뿐 · **진단·발달 평가 표현 금지**("진단이 아니라 대화 가이드") · AI 결합 단계부터는 비공유 데이터 차단 관문(GiftGate)을 먼저 구축 |
| 1기 | 잔여 다듬기 | 실패를 아이 탓으로 돌리지 않는 문구 완결 · "키디가 걸러낸 영상" 카드(검수가 일하고 있음을 부모가 보게) · 외부 장애 시 대체 안내 (한계 #4) |
| 2기 | ★ **위기 감지 근본 개선** | 금지어 목록 방식 → 아동보호 공식 매뉴얼 등 공개 표준 기반 재설계 + 감지 이후 대응 절차. 판단마다 출처를 남깁니다 (한계 #1·#2) |
| 2기 | ★ **개인정보 체계 완결** | 처리방침 완성(조항마다 앱의 실제 동작과 대조 확인) · 법정대리인 동의 절차 구현 · 아이가 주인공인 민감한 일화를 걸러내는 검수 항목 신설 (한계 #7) |
| 2기 | ★ **온기 서랍** — 익명 위로 편지 | 검수를 통과한 부모들의 편지가 익명 서랍에 쌓이고, 힘든 날의 부모가 한 통을 꺼내 읽습니다(하루 1통).<br>부모 마음 체크인(키디가 부모에게도 안부를 묻는 기능)을 입구로 포함 · 5단계 검수(자동 필터 → AI 판정 → 고쳐쓰기 안내 → 위기 시 돌봄 전환 → 운영자 전량 확인) |
| 2기 | ★ **가족 사진 첨부** | 부모가 가족 책장의 일기마다 **그날의 실제 사진**을 붙일 수 있게 — 업로드 전 자동 압축으로 용량 최소화. 3기 가족 앨범의 재료가 됩니다 |
| 3기 | ★ **가족 앨범 3단계** | ① 골라서 내려받기(ZIP/PDF) ② 월별 디지털 앨범 ③ **영상 앨범** — 아이 목소리가 내레이션이 되는 30~60초 세로 영상, 내보내기까지(앱 안에 SNS 공유 버튼은 만들지 않음 — 아동 노출 최소화 원칙) + 실물 인쇄는 인쇄용 파일과 시제품 제작까지.<br>🔴 **판매는 범위 외** — 결제·사업자등록 이후의 일로 명시 |
| 3기 | ★ **'작년 오늘' 타임캡슐** | 아이의 예전 목소리·그림이 1년 뒤 가족에게 도착 — 새로 수집하는 데이터 없이 기존 기록의 재구성 |
| 3기 | 실기기 검증 | 핵심 여정(체크인→시청→일기→부모 리포트)을 실제 아이폰·안드로이드 기기에서 확인 (한계 #6) |
| 승격 대기 | **느린 우체국** (1:1 편지 배달) | 온기 서랍의 운영 수치(신고율·검수 정확도)가 기준을 통과하면 승격 — 검수 체계를 공유하므로 서랍이 완성되면 준비의 80%가 끝나 있습니다 |
| 여력 시 | 가족 왕복 우체국 | 아이가 부모에게 질문을 골라 배달 · "같이 보고 싶어" 주말 예약 |

### 3-2. "다 됐다"의 기준 — 4개 통과 기준

### 3-3. 기술적 검토

## 5. 보안 취약점 — 지키는 방식과 점검 계획

> 보안은 한 번 점검하고 끝나는 목록이 아니라 **계속 도는 자동 장치**로 지키고 있습니다.
> 세부 취약점은 고도화 기간 중 정기 점검으로 찾아 고치고, **조치 이력과 함께 완료 보고서에 담겠습니다.**

**지금 상시 가동 중인 자동 장치** — 코드를 반영할 때마다 자동으로 검사하고, 걸리면 반영 자체가 막힙니다

| 무엇을 막나 | 어떻게 |
|---|---|
| 아무나 서버에 접근하는 것 | 서버의 모든 출입구(83개)마다 "누가 열 수 있는가"를 정해 두고, 지켜지는지 자동 확인 |
| 다른 가족의 데이터를 보는 것 | 남의 아이 데이터에 닿는 길이 생기면 자동 차단 |
| **아이의 비밀이 부모 화면으로 새는 것** | 아이가 공유하지 않은 이야기가 부모 쪽으로 새는 길이 생기면, 그 코드는 반영되기 전에 걸립니다 |
| 위기 상황의 아이 말이 밖으로 나가는 것 | 화면 표시·음성 변환보다 **먼저** 위험 신호를 검사하는 순서를 자동 확인 |
| 해킹·오남용으로 AI 비용이 폭주하는 것 | 계정·아이별 사용 한도 + 한도에 막힌 뒤 외부 호출이 0회인지까지 확인 |
| 비밀 키가 코드 저장소에 올라가는 것 | 키가 담긴 파일은 유형 전체를 커밋(반영) 단계에서 차단 |

**고도화 기간의 점검 계획**
- 각 기(4주) 말에 자체 보안 점검 → 발견·조치 이력 누적
- 3기: 실기기·배포 환경 설정 점검 포함 최종 점검 → **보안 점검 결과서** 제출
- KT 측에 요구 보안 기준이 있다면 회신 주시면 그 기준에 맞춰 점검하겠습니다
