# 그림일기·체크인 — 보유와 파기 설계

작성: 2026-08-08 · 상태: **🟡 방향만 정함. 결정 아님.**
계기: 오너 질문 — *"부모 주간 리포트에 쓰는 아이들 인터뷰 텍스트는 얼마나 가지고 있고, 어디에 저장되며, 언제 지워져?"*

> **이 문서의 성격**: 답을 확정한 문서가 아니다. **오늘 실측으로 알아낸 사실**과
> **오너와 합의한 방향**, 그리고 **아직 답이 없는 것**을 한곳에 모은다.
> 앨범 기능을 정할 때 이 문서부터 열면 처음부터 다시 파지 않아도 된다.
>
> ⚠️ 지금 결정하지 않는 이유(오너): **피지컬/디지털 앨범을 만들지 자체가 미확정**이다.
> 그걸 파기 트리거로 삼는 규칙을 먼저 정하면 순서가 거꾸로다.

## 1. 실측 — 지금 실제로 이렇다 (2026-08-08)

### 어디에 저장되나 — **같은 내용이 두 곳에**

| 테이블 | 무엇 | 비고 |
|---|---|---|
| `daily_checkins.answers` (jsonb) | 아이가 고르거나 **말한 답변 원문** | 🚨 비공개 선택 시 빈 배열 — **서버가 강제** |
| `parent_reports.shared_highlights` (jsonb) | 리포트 만들 때 **답변을 복사해 넣은 사본** | 참조가 아니라 **복사**다 |

🔴 **`answers` 만 지워도 같은 내용이 `parent_reports` 에 남는다.** 파기를 설계할 때 반드시 둘 다 봐야 한다.

### 얼마나 — **무기한**

```
자동 파기 배치: 0건
```
`checkins.py` 에 삭제 코드가 한 줄도 없다. `cleanup_orphan_data.py` 도 체크인은 안 건드린다.
**아이가 3살에 한 말이 13살이 돼도 그대로 남는다.**

### 언제 지워지나 — 세 경우뿐

| | |
|---|---|
| 아이 프로필 삭제 | ✅ `on delete cascade` — 체크인·리포트 함께 |
| 회원 탈퇴 | ⚠️ 연쇄 삭제는 되나 **탈퇴 API 미구현**(이메일 수동 접수) |
| 그 외 | ❌ 아무 일도 안 일어남 |

**아이는 자기 체크인을 개별로 지울 수 없다.** 부모가 프로필을 통째로 지우는 경로뿐이다.

### 음성이 저장되는 범위 — 두 갈래를 혼동하지 말 것

| | 어디 | 저장 형태 |
|---|---|---|
| **녹음 파일** | 그림일기에만 (`DiaryFlow` 아이 메모 · `ParentDiaryShelf` 부모 편지) | 음성 파일. **글자 변환 없음**(transcript 컬럼 자체가 없음) |
| **말 → 글자** | 체크인 · 그림일기 · 챗 · 키디의 방 (`useKiddySpeech` 4곳) | 텍스트. 체크인은 **공유 선택 시만** 저장 |

⚠️ 처리방침에 *"아이 음성은 그림일기에만"* 이라고 쓰면 **부정확**하다. 체크인에서 말로 답한 것이 빠진다.

### 미구현 — '전달' 단계가 아직 없다

| 기능 | 화면 |
|---|---|
| 타임머신 | **0곳** |
| 타임캡슐 | **0곳** |
| 키디 졸업 | **0곳** |
| 앨범 | 2곳 (책장 UI뿐 — 인쇄·내보내기 아님) |

2026-07-12 유실 후 재구현되지 않았다(`DECISIONS.md`). 설계는 공모전 신청서에 생존.

## 2. 방향 — 오너와 합의한 것 (결정 아님)

### ① 승격 후 파기 (promote-then-purge)

```
아이 답변 (daily_checkins.answers)
   ↓ 주간 리포트 생성 = 1차 승격
주간 리포트 (parent_reports)
   ↓ 앨범·영상 = 부모 손으로 전달
실물 / 파일  ← 우리 서버 밖
```

법 제21조(*"목적 달성 후 지체 없이 파기"*)를 정면으로 만족시킨다.
**단계마다 다음으로 넘기면 이전 것은 목적이 끝난다.**

### ② 기본 3년 + **앨범을 만들면 그 기간 파기**

> 오너: *"기본 소유는 3년으로 하되, 부모가 디지털 or 피지컬 앨범을 만들면 파기."*

**이 설계의 진짜 강점은 파기를 '상실'이 아니라 '완성'으로 바꾼다는 것이다.**

| | 사용자가 듣는 말 |
|---|---|
| 그냥 3년 파기 | *"3년 지나면 사라집니다"* → 나쁜 소식 |
| 앨범 = 파기 시점 | *"앨범으로 만드시면 그때 정리됩니다"* → **완성** |

종이 사진첩과 같은 원리다 — **실물이 생기면 원본은 역할을 다한다.**
그리고 앨범이 프리미엄 1순위이므로, **파기 시점이 곧 앨범을 만들 진짜 이유**가 된다(억지 압박이 아니라).

### ③ 🔴 파기 전 **무료 내려받기**를 반드시 함께 제공한다

> *"○○의 2026년 기록을 정리할 때가 됐어요.
> **무료로 내려받으시거나**, 앨범으로 만들어 드릴게요."*

이게 없으면 *"돈 안 내면 아이 추억이 사라집니다"* 가 된다 — 오늘 그은 선을 넘는다.
있으면 **"직접 챙기시거나, 저희가 예쁘게 만들어드리거나"** 가 된다.
페르소나(키디는 인질을 잡지 않는다)와 맞고, 법 제35조(열람)·데이터 이동에도 부합한다.

### ④ 안내 방식 — 상시 + 임박 1회

> 오너: *"상시 안내문 같은 걸로 설명해 놓고, 앨범·영상 만드는 메뉴를 신설할 때 그 안에 적용."*

| | |
|---|---|
| **상시 안내문** (앨범 메뉴 안) | 맥락 있는 자리에서 읽는 게 뜬금없는 팝업보다 잘 전달된다 |
| **파기 임박 시 1회** | 앱 열면 보이는 배너. **반드시 무료 내려받기와 함께** |

⚠️ 상시 안내문만 두면 **그 메뉴에 안 들어간 사람은 영영 모른다.** 파기는 되돌릴 수 없다.
⚠️ 반대로 무료 선택지 없이 알리면 압박이 된다. **둘이 같이 있어야 성립한다.**

### ⑤ 디지털 앨범 = **영상**

> 오너: *"디지털 앨범은 영상 형식으로 보여줘도 나쁘지 않을 것 같네. 파일로도 가질 수 있고."*

**재료가 이미 다 있다:**

| 우리가 가진 것 | 영상에서 |
|---|---|
| 그림 (1536×1024) | 화면 |
| 일기 문장 | 자막 |
| **아이 음성 메모** | 🎯 **내레이션** |
| 부모 음성 편지 | 마지막 장면 |
| 기분 이모지·날짜 | 흐름 |

🎯 **목소리가 결정적이다.** 종이 앨범엔 못 담는 게 그거다. **세 살 목소리는 다시 못 듣는다.**

**"부모가 올리고 싶어지게" 만든다** (오너 의도 — 앱 안에 공유 버튼을 만들자는 뜻이 **아니다**):

| | 왜 |
|---|---|
| 세로 9:16 | 릴스·스토리 규격. 가로로 만들면 안 올린다 |
| 30~60초 | 그 이상은 안 본다 |
| 아이 목소리를 살린다 | 공유 욕구의 핵심. 그림만 있으면 안 올린다 |
| 워터마크 최소 | 광고처럼 보이면 안 올린다 |

### ⑥ 내보내기까지만 — **SNS 공유 버튼은 만들지 않는다**

| | |
|---|---|
| ✅ 영상 파일 내려받기 | 부모 기기에 저장. 그다음은 부모 자유 |
| ❌ 앱 안의 "인스타에 공유" 버튼 | 만들지 않는다 |

차이는 미묘해 보이지만 크다 — **우리가 권하지 않는다.**
부모는 원하면 어차피 올린다. 우리가 안 만들어도. 다만 **부추기지는 않는다.**

내보낼 때 한 줄만 덧붙인다(막는 게 아니라 **먼저 말해주는 것**):
> *"이 영상에는 ○○의 **목소리**가 담겨 있어요."*

> 배경: 아동 콘텐츠의 부모 공개(sharenting)는 논쟁 영역이다. 프랑스는 2024년 관련 입법을 했고
> 한국도 논의가 있다. 한 손으로 *"아이의 비밀을 지킵니다"* 하면서 다른 손으로 공유를 부추기면 모순이 된다.

## 3. 🔴 아직 답이 없는 것

| # | 질문 | 왜 어려운가 |
|---|---|---|
| 1 | **3년의 근거** | 법정 기준이 아니다. 3살 시작 → 6살(초등 전)이라 감은 좋으나 그건 감이다. 전문가 확인 필요(B1 부록 A #17) |
| 2 | **부분 파기 범위** | 앨범은 특정 기간만 뽑는다. "앨범 만들면 전부 파기"가 아니라 **담긴 기간만** 파기여야 한다 |
| 3 | **앨범 후 앱 책장은?** | 파기하면 앱이 빈다. *"돈 내고 만들었더니 앱에서 사라졌네"* 는 나쁜 경험. **"실물이 원본이 됩니다"** 를 미리 명확히 해야 한다 |
| 4 | **떠난 사용자 통지** | 우리는 **푸시가 없다.** 앱 내 배너뿐이라 떠난 부모에게 안 닿는데, 정작 데이터를 잃는 건 그쪽이다 |
| 5 | **영상 인코딩 원가** | 클라이언트(Canvas+MediaRecorder, 0원·폰에서 느림) vs 서버(ffmpeg, CPU 비용 큼·Railway면 비쌈). **원가에 직결** |
| 6 | **`parent_reports` 사본 처리** | 답변이 복사돼 있다. 원본만 지우면 파기가 아니라 중복 제거일 뿐 |
| 7 | 아이의 개별 삭제권 | 지금은 프로필 통째 삭제뿐. 아이가 자기 체크인을 지울 방법이 없다 |

## 4. 순서 — 되돌릴 수 없는 것을 나중에

```
1. 앨범·영상 구현            ← 전달 경로가 먼저
2. '전달 완료' 기록          ← 무엇이 언제 넘어갔는지
3. 그 다음 파기              ← 되돌릴 수 없다
```

🔴 **복사가 확인된 뒤에 파기한다.** 007 SQL 에 적어둔 원칙과 같다 —
반대로 하면 *"앨범 만들다 실패했는데 원본은 이미 없는"* 상태가 된다.

⇒ **전달 경로가 없는 지금 파기부터 만들면 그냥 버리는 것이다.**

*"그해 여름은 대체로 밝았다"* 는 남길 가치가 있다.
**무거운 건 원문이고, 오래 가는 가치는 집계에 있다.** 타임캡슐이 나중에 생겨도 재료는 온전하다.
