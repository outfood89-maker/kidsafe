## 제7조 (만 14세 미만 아동의 개인정보 처리)

「개인정보 보호법」 **제22조의2(만 14세 미만 아동의 개인정보 처리에 관한 특례)**에 따라 다음과 같이 처리합니다.

1. 서비스의 이용자는 만 14세 미만 아동이며, **아동은 스스로 회원가입할 수 없습니다.** 계정은 보호자만 생성할 수 있고, 아동은 보호자 계정 하위의 프로필로만 존재합니다.
2. 회사는 만 14세 미만 아동의 개인정보를 처리하기 위해 **법정대리인(보호자)의 동의를 받으며, 법정대리인이 동의하였는지를 확인합니다**(같은 조 제1항).
3. 회사는 아동에게 개인정보 처리에 관한 사항을 **이해하기 쉬운 양식과 명확하고 알기 쉬운 언어로** 별도 안내합니다(같은 조 제3항). 본 방침의 '문서 2 — 키디의 약속'이 이에 해당하며, 글을 읽지 못하는 연령을 고려하여 음성으로도 안내합니다.
4. 회사는 아동에게 **개인정보 제공에 대한 대가로 보상이나 혜택을 제공하지 않습니다.** 체크인·미니게임의 보상은 '참여했다'는 사실에만 지급되며, 무엇을 답했는지는 보상에 영향을 주지 않습니다.
5. 회사는 **아동에게 광고를 게재하지 않으며, 아동의 개인정보를 광고 목적으로 이용하지 않습니다.**
6. 회사는 아동의 비공개 선택을 존중합니다. 아동이 '비밀'로 표시한 답변 내용은 보호자에게 제공되지 않으며 서버에 저장되지도 않습니다. **다만 아동의 안전이 걱정되는 신호가 감지된 경우, 회사는 그 사실(내용은 제외)을 보호자에게 알립니다.**

> **[확인 필요 — 중대]** 위 제2항은 **현재 코드에 구현되어 있지 않습니다.** 회원가입 화면(`client/src/pages/Login.jsx`)은 이메일·비밀번호·보호자 닉네임만 받으며, **동의 체크박스도, 동의 기록을 저장하는 테이블·컬럼도 존재하지 않습니다.** 법 제22조의2제1항은 동의를 받을 것과 **동의 여부를 '확인'할 것**을 함께 요구하므로, "프로필 생성 = 동의"라는 해석으로 갈음할 수 있는지 전문가 확인이 반드시 필요합니다. **동의 절차와 동의 기록 보관을 구현하기 전에 이 조항을 공개하면 허위 기재가 됩니다.**
>
> **[확인 필요]** 법정대리인의 동의 여부를 확인하는 구체적 방법(신용카드 인증, 휴대전화 본인확인 등)은 「개인정보 보호법 시행령」에 규정돼 있습니다 — **[확인 필요: 시행령 조문 번호와 허용 수단 목록의 최신본]**. 현재 서비스는 이메일 가입만으로 성인 여부를 전혀 확인하지 않습니다.

1. 보호자는 아동의 법정대리인으로서, 그리고 본인의 정보주체로서 「개인정보 보호법」 **제4조** 및 **제35조(열람)·제36조(정정·삭제)·제37조(처리정지)**에 따라 언제든지 다음 권리를 행사할 수 있습니다.
   - 개인정보 **열람** 요구
   - 오류 등이 있을 경우 **정정** 요구
   - **삭제** 요구
   - **처리정지** 요구
2. 앱 안에서 직접 가능한 것:
   - 아동 프로필 정보 수정 및 프로필 삭제(**프로필 삭제 시 그 아이의 모든 기록이 함께 삭제됩니다**)
   - 시청 기록 개별/전체 삭제
   - 검색 기록 개별/전체 삭제
   - 찜 목록 삭제, 일정 삭제, 차단 키워드 삭제
   - 그림일기의 개별 페이지 삭제(그림·음성 포함 즉시 완전 삭제, 복구 불가)
   - 보호자 닉네임·비밀번호 변경
3. 회원 탈퇴 및 위 방법으로 처리되지 않는 요구는 제11조의 연락처로 신청하실 수 있으며, 회사는 지체 없이 조치합니다.
4. 아동 본인도 자신의 기록(체크인 공유 선택, 그림일기 페이지 등)을 지울 수 있습니다. 다만 계정 단위의 권리 행사는 법정대리인을 통해 이루어집니다.

> **[확인 필요 — 중대]** 현재 **회원 탈퇴를 앱에서 처리하는 기능이 구현되어 있지 않습니다.** 탈퇴 화면(`client/src/pages/Account.jsx`)은 존재하고 "탈퇴" 입력 확인까지 받으나, 실행 시 `alert("회원 탈퇴는 현재 관리자에게 문의해주세요. (outfood89@gmail.com)")` 안내만 표시되고 실제 삭제 API 호출이 없습니다. 이메일 접수 후 수동 처리하는 방식이 법상 "지체 없이"에 부합하는지, 자동화가 필요한지 확인이 필요합니다.

## 제9조 (개인정보의 파기)

「개인정보 보호법」 **제21조**에 따라 다음과 같이 파기합니다.

1. 회사는 보유 기간이 경과하거나 처리 목적이 달성된 경우 지체 없이 개인정보를 파기합니다.
2. 파기 절차 및 방법:
   - **전자적 파일**: 데이터베이스에서 삭제하여 복구·재생할 수 없도록 처리합니다. 아동 프로필 또는 회원 계정이 삭제되면 그에 종속된 모든 데이터가 데이터베이스의 연쇄 삭제(on delete cascade) 설정에 따라 자동으로 함께 삭제됩니다.
   - **자동 파기**: 시청 기록은 계정당 최근 50건을 초과하면 오래된 순으로 자동 삭제됩니다.
   - **기기 내 저장 정보**: 이용자가 앱에서 삭제하거나 브라우저 데이터를 삭제하면 즉시 파기되며 복구할 수 없습니다.
3. 아동이 체크인에서 비공개를 선택한 답변 내용은 **애초에 저장되지 않으므로 파기 대상이 존재하지 않습니다.**

> **[확인 필요 — 중대]** 현재 **보유 기간 경과에 따른 자동 파기 로직이 구현되어 있지 않습니다.** 구현된 것은 시청 기록 50건 상한과 사용자의 명시적 삭제 요청뿐입니다. 검색 기록·체크인·리포트·알림·일정·케어 신호는 삭제 요청이 없으면 무기한 남습니다. 법정 보유 기간 상한을 정하고 배치 파기를 구현해야 하는지 확인이 필요합니다.

## 제10조 (개인정보의 안전성 확보 조치)

「개인정보 보호법」 **제29조** 및 「개인정보의 안전성 확보조치 기준」(개인정보보호위원회 고시)에 따라 다음의 조치를 시행하고 있습니다.

1. **관리적 조치**: 개인정보 취급자를 최소화하고, 관리자 기능 접근 시 권한(role)을 검증하며, 관리자 활동을 감사 로그로 기록합니다.
2. **기술적 조치**
   - 모든 통신은 HTTPS로 암호화됩니다.
   - 인증은 서명 검증이 가능한 토큰(JWT, 공개키(JWKS) 기반 ES256/RS256 검증) 방식으로 처리하며, 개인 데이터 접근 시 계정 소유권과 프로필 소유권을 매 요청 검증합니다.
   - 아동 데이터 테이블(프로필·시청·검색·찜·배지·보너스·체크인·리포트·일정·알림·케어 신호 등)은 행 수준 보안(RLS)이 활성화되어 있고 정책을 두지 않아, **클라이언트에서 데이터베이스로의 직접 접근이 차단**되고 서버를 경유한 접근만 허용됩니다.
   - **[확인 필요 — 정정 사항]** 다만 `accounts`·`subscriptions`·`payments`·`donations` 4개 테이블에는 "본인 데이터만 조회" RLS 정책이 부여되어 있어, 로그인한 클라이언트가 자신의 행을 직접 조회할 수 있습니다. 따라서 "전면 차단"은 아동 데이터 테이블에 한한 표현이며, 위 4개 테이블은 정책 기반 접근 제어가 적용됩니다.
   - 보호자 확인용 PIN은 평문으로 저장하지 않고 PBKDF2-HMAC-SHA256 100,000회 반복 해시와 16바이트 임의 salt로 저장하며, 검증 시 타이밍 공격에 안전한 비교(`hmac.compare_digest`)를 사용합니다.
   - 외부 API 키는 소스코드에 포함하지 않고 서버 환경변수로만 관리하며, 오류 로그에 기록되지 않도록 처리합니다.
   - 아동의 위기 신호는 내용을 저장할 수 있는 데이터 항목 자체를 두지 않는 방식으로, 구조적으로 기록이 남지 않게 설계했습니다.
   - 위기 신호가 감지된 발화는 AI 호출 전에 차단되어 외부로 전송되지 않습니다.
3. **[확인 필요 — 보완 권고]** 아래는 방침에 쓰기 전에 코드 수정이 선행되어야 합니다.
   - 서버의 CORS 설정이 모든 출처를 허용(`server/main.py`: `allow_origins=["*"]`)하도록 되어 있습니다. 운영 도메인으로 제한할 것을 권고합니다.
   - **키디 채팅 엔드포인트(`POST /chat`)에 로그인 인증 의존성이 걸려 있지 않아 누구나 인증 없이 호출할 수 있습니다**(`server/routers/chat.py`의 `chat_with_kiddy`에 `Depends(get_current_user)` 없음). 아동의 대화 내용이 국외로 전송되는 경로이자 유료 API 남용 경로이므로 인증 적용을 권고합니다.
   - 접속 기록(로그) 보관·위변조 방지, 정기 백업·복구 절차, 접근 권한 관리 대장 등 「개인정보의 안전성 확보조치 기준」 항목의 충족 여부 전반 점검이 필요합니다.

# 부록 A. 전문가에게 물어볼 것

## A-1. 가장 급한 것 (문안 공개 전 반드시 답이 필요)

1. **법정대리인 동의를 어떻게 받아야 충분한가?**
   현재는 "보호자가 이메일로 가입하고 아이 프로필을 직접 만든다"가 전부이며, 동의 화면도 동의 기록도 없습니다. 법 제22조의2제1항의 '동의를 받고 동의 여부를 확인'하는 의무를 충족하려면 무엇이 필요한가요? 동의 시점에 무엇을 보여줘야 하나요?

2. **법정대리인임을 확인해야 하나?**
   가입자가 성인·보호자인지 확인하는 절차가 전혀 없습니다. 시행령이 정하는 확인 수단(신용카드·본인확인 등)이 요구되는 수준인가요, 아니면 아동의 직접 가입 경로가 없다는 점으로 충분한가요?

3. **아동이 비공개를 선택한 답변이 저장 전에 이미 국외(Anthropic)로 전송되는 구조를 어떻게 고지해야 하나?**
   기술적으로 회피 불가합니다(반응 생성이 곧 전송). "저장하지 않음"과 "전송함"을 함께 쓰면 이용자가 오해할 위험이 있는데, 어떤 문장 구조가 정확하면서 오해가 없나요?

4. **아이가 그린 낙서 원본이 OpenAI로 전송되고 일정 기간 보관되는 것 — 별도 동의가 필요한가?**
   아동의 창작물이자 아동이 직접 만든 이미지입니다. 처리방침 고지만으로 충분한가요, 아니면 기능 사용 시점마다 보호자의 개별 동의(민감정보에 준하는 취급)가 필요한가요?

5. **아동의 '기분' 데이터가 민감정보인가?**
   법 제23조의 민감정보(건강 등)에 해당하나요? 감정 상태를 21일에 걸쳐 추세 분석해 보호자에게 신호를 보내는 기능이 있는데, 이것이 건강정보 처리 또는 제37조의2의 자동화된 결정에 해당할 소지가 있나요?

6. **아동 보호(위기) 신호를 아동에게 알리지 않고 보호자에게 통지하는 것.**
   내용은 저장·전달하지 않고 "신호가 있었다"만 알립니다. 아동에게 이 사실을 사전 고지해야 하나요? 현재 아동용 안내에는 이 항목이 없습니다. 넣어야 한다면 4~8세에게 어떻게 표현해야 하나요?

7. **"비밀로 한 날이 있다"는 사실 자체가 보호자에게 표시되는 것.**
   비공개 체크인의 내용은 감춰지지만, 리포트에는 그 기간에 공유하지 않은 날이 있다는 신호가 뜹니다. 이를 아동에게 고지해야 하나요? 고지 없이 두면 아이가 이해한 '비밀'과 실제가 어긋납니다.

## A-2. 표기·구성에 관한 것

8. **회사 서버를 거치지 않고 이용자 브라우저가 자체 기능으로 수행하는 처리를, 처리방침 기재 범위에서 제외하기로 한 결정(오너 결정 C4).**
   "회사가 직접 보내는 것만 고지한다"는 구분이 법적으로 방어 가능한가요? 방어 가능하더라도, 이용자에게 알릴 필요가 있다면 처리방침이 아닌 다른 위치(예: 권한 요청 시 안내)가 적절한가요?

9. **Supabase의 리전이 국내(서울)일 경우에도 국외 이전으로 표기해야 하나?**
   미국 법인이 운영하는 관리형 서비스입니다. 데이터의 물리적 위치와 처리자의 국적 중 무엇이 기준인가요? 또한 가입·로그인은 이용자 브라우저가 Supabase와 직접 통신하는데, 이 경우에도 '회사의 위탁'으로 보나요?

10. **호스팅 사업자(Vercel/Railway)를 위탁·국외이전 표에 넣어야 하나?**
    Vercel은 프론트 정적 자산과 접속 로그만 다루지만, Railway는 서버가 처리하는 모든 개인정보의 실행 환경입니다. 이 둘을 같은 층위로 적어야 하나요, 구분해야 하나요?

11. **CLOVA Voice(네이버클라우드)는 국내 사업자인데 제6조(국외 이전)에서 빼도 되나?**
    데이터 처리 리전이 국내라면 제5조(위탁)에만 남기면 충분한가요?

12. **국외 이전 거부를 '탈퇴'로만 제공해도 되나?**
    핵심 기능 전부가 국외 이전에 의존합니다. 기능별 부분 거부(예: AI 그림 끄기)를 제공할 의무가 있나요?

13. **아동용 안내와 성인용 방침의 관계.**
    아동용은 별도 문서인가요, 성인용 방침의 부속인가요? 아동용에 담기지 않은 내용(외부 전송 등)이 있어도 되나요? 음성으로만 안내하고 텍스트를 두지 않아도 되나요?

14. **결제 기능이 실제로 가동되지 않는 상태(전 계정 무료 프리미엄 처리)에서, 결제 관련 수집 항목을 방침에 미리 써도 되나?** 아니면 유료화 시점에 추가해야 하나요? 결제 테이블은 이미 존재하지만 연동 코드는 없습니다.

15. **익명 신고(점수 이상 신고)에 신고자 식별정보를 저장하지 않는 것**이 오히려 문제가 되나요? 악용 대응이 불가능한데 실무상 최소한의 식별자를 남겨야 하나요?

16. **개인정보 보호책임자를 개인 개발자 본인으로 지정할 때** 공개해야 하는 최소 정보의 범위는? 개인 이메일만으로 충분한가요?
