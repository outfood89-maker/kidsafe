# [고도화 GD-38] 완벽하지 않은 키디 — 한 곳에서 옳게 한 판단을 **전부에 퍼뜨리기**

*작성 2026-08-07(팀장) · 발단: 오너가 아이디어 서랍 4·5·6을 보고 — **"이건 여러 기능에 다 적용할 수 있는 그런 기능 같은데?"***
*승격: [아이디어 서랍](../아이디어/아이디어_서랍.md) 4·5·6 → 이 문서*

> **한 줄 요약:** 이건 새 기능 3개가 아니다. **이미 한 곳에서 옳게 한 판단이 나머지에 안 퍼진 것**이다.
> ⚠️ 아래는 전부 **2026-08-07 코드 실측**이다. 착수 시점에 바뀌었으면 인용 문자열로 다시 찾을 것.

---

## §0. 왜 이게 하나의 문서인가

서랍에 던진 셋은 따로 보면 작은 UX 개선이다. 그런데 오너가 *"여러 기능에 다 적용할 수 있는 것"* 이라고 짚은 순간 공통 축이 드러났다.

| 아이디어 | 실은 무엇인가 |
|---|---|
| 4 키디 귀 | **실패를 아이 탓으로 만들지 않는다** |
| 5 나도 몰라 | **모르는 걸 인정하고 거기서 멈추지 않는다** |
| 6 엄마도 일곱 살 | **관계가 한 방향으로만 흐르지 않는다** |

셋 다 **"키디를 완벽한 도구가 아니라 불완전한 동행자로 두는" 설계**다.
이건 정체성 문서의 *"정체성(B)=관계 / 해자(A)=검수"* 와 정확히 같은 축이다 — **완벽한 검수 도구는 A를 강화하지만, 불완전한 친구는 B를 만든다.**

🔴 **그리고 실측해보니 셋 중 둘은 이미 우리가 옳게 판단한 적이 있다. 안 퍼졌을 뿐이다.**

## §1. 원칙 A — **실패는 키디 탓이다** (아이 탓으로 만들지 않는다) ✅ **완료 2026-08-07**

> **처리 완료** (커밋 `247117b`) — `KidHome.jsx:591`·`KiddyRoom.jsx:36` 두 곳의 문구를
> **"어? 잘 못 들었어. 한 번만 더 말해줄래?"** 로 교체. 로직 무변경 · 224건 통과 · 오너 시범테스트 확인.
> 남은 것: **§1 뒤쪽의 "키디 귀" 연출**(아래) 은 미착수.
>
> 📌 **작업 중 확인된 것** — 인식 실패 문구는 화면마다 미묘하게 다르다.
> 체크인 *"잘 못 들었어. 다시 말해줄래? 🎤"* / 키디의 방·검색 *"어? 잘 못 들었어. 한 번만 더 말해줄래?"* / 그림일기 *"어? 잘 못 들었어! 다시 말해줄래?"*
> **셋 다 '키디 탓' 톤이라 원칙은 충족**한다. 한 문장으로 통일할지는 별건(오너 판단 대기).

### 이미 옳게 한 곳 — 오너가 직접 세운 원칙

`client/src/utils/diaryCopy.js:122`

```js
retry: "어? 잘 못 들었어! 다시 말해줄래?",
// 오너 개정(7/8): "그럼~"은 못 알아들은 상황에 어색 → 못 들은 걸 먼저 인정(아이 탓 아님)
```

**주석에 판단 근거까지 적혀 있다.** 2026-07-08 오너가 직접 고친 자리다.

### 아직 안 퍼진 곳 (실측)

| 위치 | 현재 문구 | 문제 |
|---|---|---|
| `pages/KidHome.jsx:587` | *"**아무 소리도 안 들렸어요.** 다시 눌러서 말해봐요!"* | 🔴 **아이가 말을 안 한 것**으로 읽힌다. 실제로는 인식이 실패한 것일 수도 있다 |
| `pages/KiddyRoom.jsx:33` | 같은 문구 (`LINE_NOSPEECH` — KidHome 복사본) | 🔴 동일 |
| `components/DailyCheckin.jsx:421` | *"잘 못 들었어. 다시 말해줄래? 🎤"* | ✅ 키디 탓 — OK |
| `pages/KidHome.jsx:589` | *"지금은 잘 안 들려. 잠깐 뒤에 다시 해볼래?"* | ✅ OK |

**→ 고칠 곳은 사실상 `LINE_NOSPEECH` 계열 2곳뿐이다.** 문구만 바꾸면 된다.

### 여기서 한 발 더 (서랍 4의 원안)

문구를 고치는 데서 멈추지 않고, **키디가 자기 상태로 말하게** 한다.

> *"키디 귀가 오늘 좀 먹먹하네. 한 번만 더 말해줄래?"* → 성공하면 키디가 귀를 쫑긋

**왜:** 말이 느리거나 발음이 서툰 아이에게 **마이크는 실패가 쌓이는 자리**다.
아이는 "내가 잘못 말했나"로 받아들이고, 그게 반복되면 마이크 자체를 안 쓰게 된다.
**책임의 주어를 바꾸는 건 문구 한 줄인데, 아이가 받는 메시지는 정반대다.**

## §2. 원칙 B — **"모른다"에서 멈추지 않는다**

### ⚠️ 먼저 정정 — 서랍 5의 근거는 틀렸다

서랍에 *"하네스엔 그 규칙이 있는데 정작 키디에는 없다"* 라고 썼는데 **사실이 아니다.**
실측하니 **LLM 경로 5곳 전부**에 이미 지침이 있다:

| 파일 | 지침 |
|---|---|
| `chat.py:74` | *"모르는 건 솔직하게 «키디도 잘 모르겠어!» 라고 해"* |
| `checkins.py` · `kiddy_greeting.py` · `schedules.py` · `reports.py` | 각각 '모른다/지어내지 말라' 계열 지침 보유 |

(팀장이 `chat.py` 한 곳만 보고 단정했다 — **오늘 하루에 세 번째 같은 실수**다: *"있는 것을 없다고 함"*.)

### 그렇다면 진짜 빈 곳은 어디인가

**"모른다"고 말한 뒤가 없다.** 지금 지침은 전부 *"지어내지 마라"* 라는 **금지**이고, 그 다음 행동을 주지 않는다.

```
지금:  아이 "블랙홀은 왜 까매?"  →  키디 "키디도 잘 모르겠어!"  →  ...끝
```

아이 입장에서 이건 **막다른 길**이다. 그리고 우리에겐 **이미 안전한 검색 기능이 있다.**

```
제안:  키디 "키디도 잘 모르겠어. 같이 찾아볼까?"  →  [영상 검색으로 연결]
```

**왜 키디여야 하나:** 요즘 아이는 AI 를 **전지전능한 존재**로 배운다.
*"모른다"* 를 말하는 AI 를 처음 만나는 게 키디였으면 좋겠고, 더 중요하게는 **모른다고 끝나지 않고 같이 찾는 경험**이 미디어 리터러시의 첫 조각이다.
(F3「리터러시 한 스푼」은 보류됐지만, 이건 **가르치지 않고 행동으로** 보여주는 다른 각도다.)

⚠️ **주의:** 검색 연결은 **아이 안전 검색어 변환(`toKidQuery`)을 반드시 거쳐야** 한다. 그리고 모든 질문에 검색을 붙이면 대화가 끊긴다 — **아이가 "응"이라고 할 때만.**

## §3. 원칙 C — **관계는 양방향이다**

### 지금 구조 (실측)

| 방향 | 있나 |
|---|---|
| 아이 → 부모 (아이가 공유 선택한 것) | ✅ 주간 리포트 |
| 부모 → 아이 (음성편지·도장) | ✅ `diaryCopy.js:252` *"엄마아빠가 도장이랑 편지를 남겼어!"* |
| **부모 자신의 이야기 → 아이** | ❌ **없다** |

리포트의 목적은 `reports.py:452` 에 이렇게 적혀 있다:

> *"부모가 오늘 저녁 아이에게 '그대로 말할 수 있는' 대화 한 줄을 준다"*

즉 지금 리포트는 **부모가 아이를 관찰하고 → 아이에게 말을 거는** 한 방향이다.
**부모가 자기 이야기를 꺼내는 자리는 한 줄도 없다.**

### 제안 (서랍 6)

주간 리포트 끝에 부모에게 **질문 하나**를 건다.

> *"일곱 살 때 제일 무서웠던 게 뭐였나요?"*

부모가 답하면 그건 리포트에 남지 않고 **아이에게 음성편지로 간다.**

**재료가 이미 다 있다** — 음성편지(부모→아이) · 녹음 UI · 리포트 발송 시점. **새로 만들 건 질문 목록과 트리거뿐이다.**

**왜 키디여야 하나:** *"아이가 부모의 어린 시절을 아는 순간"* 은 이 앱이 만들 수 있는 **가장 값싼 감동**이다.
그리고 이건 데모의 심장(*"부모가 리포트를 열고 뭉클해진다"*)을 **한 번 더 뒤집는다** — 부모가 뭉클해지는 게 아니라, **부모가 아이를 뭉클하게 만든다.**

## §4. 착수 순서 (팀장 권고)

| 순 | 무엇 | 크기 | 왜 이 순서 |
|---|---|---|---|
| 1 | **원칙 A — `LINE_NOSPEECH` 계열 2곳 문구 교체** | 🟢 매우 작음 (문구만) | 오너가 이미 다른 곳에서 내린 판단을 맞추는 것. **논쟁 여지가 없다** |
| 2 | **원칙 A 확장 — 키디 귀 연출** | 🟡 작음 | 문구 + 포즈/애니메이션 1개 |
| 3 | **원칙 B — "같이 찾아볼까?"** | 🟡 중간 | 프롬프트 + 검색 연결 + 안전 검색어 변환 경유 |
| 4 | **원칙 C — 부모에게 묻기** | 🟠 중간~큼 | 질문 목록 설계 + 리포트 UI + 음성편지 연결. **질문 문구가 핵심**(잘못 쓰면 숙제가 된다) |

### 공통 주의 — 윤리선

- 🔴 **의무·압박 금지.** 원칙 C 의 질문에 부모가 답하지 않아도 **아무 일도 일어나지 않아야** 한다. "답하지 않으셨어요" 류 알림 금지.
- 🔴 **원칙 B 의 검색은 아이 안전 검색어 변환을 반드시 경유.**
- 원칙 A 는 **키디가 무능해 보이게 만들지 않는다.** *"키디 귀가 먹먹하다"* 는 귀엽지만, 반복되면 신뢰가 깎인다 → **연속 실패 2회 이상이면 칩 선택 폴백**(이미 `DiaryFlow` 에 `REASK.fallback` 선례 있음).

## §5. 이 문서의 진짜 교훈 (팀장 메모)

**아이디어 3개 중 2개는 "새로 만들 것"이 아니라 "이미 옳게 한 걸 퍼뜨릴 것"이었다.**
그리고 그 사실은 **코드를 열어보고서야** 알았다 — 서랍에 쓸 때는 몰랐고, 근거 하나는 틀리게 썼다.

> 📌 **아이디어를 승격시킬 때는 "이미 어딘가에 있지 않나"를 먼저 실측한다.**
> 좋은 판단은 보통 **한 번은 이미 내려져 있다.** 그게 안 퍼졌을 뿐이다.
> (2026-08-07 하루에 *"있는 것을 없다고 함"* 을 세 번 했다 — 그림일기 한도 · 위기 사전 · 이 문서의 원칙 B.)
