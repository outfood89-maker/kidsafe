### 지켜야 할 제약

1. **응답 JSON의 기존 필드를 하나도 없애지 않는다.** 프론트가 `report.moodSummary?.counts` 같은 옵셔널 체이닝과 spread 계보를 쓰므로, 폴백 응답도 **정상 응답과 같은 키 집합**을 유지하고 부족한 부분만 `""` / `[]` / `null`로 채운다. 추가는 **additive만** (`degraded`, `degradedReason` 2개).
2. **LLM 실패와 DB 실패를 구분한다.**
   - LLM 실패(Anthropic 오류·JSON 파싱 실패·빈 편지) → **200 + 부분 리포트**.
   - 핵심 재료 조회 실패(`daily_checkins` 본조회, `reports.py:607-616`) → **기존대로 502 유지.** 재료가 없으면 타임라인 자체를 만들 수 없다. 이때 프론트는 지금의 에러 카피 그대로.
   - 부수 조회 실패(패턴 신호용 21일 조회 `593-603`, 캐시 조회 `635-642`) → **502로 죽이지 말고 그 기능만 degrade.**
3. **폴백 리포트를 `parent_reports`에 저장하지 않는다.** 저장하면 캐시 신선도 검사(`643-651`, `created_at >= latest`)에 걸려 **빈 편지가 그 주 내내 굳는다.** 이 지시서에서 가장 중요한 함정이다.
4. **`empty` 플래그를 쓰지 않는다.** 폴백은 `empty=False`다. `True`로 두면 프론트 **122줄**에서 조기 리턴돼 "아직 이번 주 기록이 없어요"라는 **거짓말**이 나간다.
5. **빈 편지 = 실패 판정은 보존한다.** 현재 **664-665줄**의 `if not kiddy_message: raise ValueError("빈 메시지")`가 하는 판정(편지가 비면 정상 아님)을 제어 흐름만 바꿔 그대로 유지한다. 판정 자체를 없애지 말 것.
6. **윤리선:** 폴백 경로에서도 `_has_secrets`(**424-432**)는 boolean만, `_compute_pattern_signal`(**513-547**)은 `mood`·`checkin_date`만 읽는다. 비공유 체크인의 `answers`에 접근하는 코드를 새로 만들지 말 것.
7. **부모에게 보이는 카피는 §3 확정문 verbatim.** 작업자 임의 창작 금지.
8. 코드 규칙: 함수형 컴포넌트만 / Axios만(fetch 금지) / Tailwind만 / try-catch 필수 / 주석 한국어.
9. **기존 코드 삭제 금지.** 이 지시서의 어떤 항목도 기존 줄의 **삭제**를 요구하지 않는다. 제어 흐름 변경은 **기존 줄을 다른 위치로 이동하거나 조건 분기의 한 가지로 감싸는 방식**으로만 한다. 끄고 싶은 것이 생기면 삭제가 아니라 **주석 처리**하고 §4에 보고한다.

            "shared_highlights": highlights, "kiddy_message": "", "created_at": None,

        return {
            "report": _report_to_api(
                degraded_row, timeline, had_secrets=had_secrets, empty=False,
                pattern_signal=pattern_signal, degraded=True, degraded_reason="llm",
