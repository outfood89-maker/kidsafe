# 🚀 고도화 — 공모전 이후 실행 자산 (착수 예정 2026-08-17)

> **이 폴더는 무엇인가**
> 공모전 이후 고도화의 **모든 계획·근거·작업지시서**를 한곳에 모은다. KT 멘토·심사위원에게 설명할 때, 그리고 8/17 착수 시 **이 폴더 하나만 열면 된다.**
>
> **운영 규칙**
> - **파일명은 `GD-번호_기능이름`으로 시작한다** (예: `GD-1_선택지순서무작위화.md`). 문서 안 제목과 파일명의 ID가 항상 일치해야 찾을 수 있다.
> - 기능 문서가 **1개**면 `기능별/`에 파일로, **2개 이상**(브리프 여러 장 or 사전조사 포함)이면 **폴더로** 묶는다 (폴더명도 `GD-번호_기능이름`).
> - 브리프를 만들 때마다 아래 체크리스트에 ✅. **빠짐없이 만드는 것이 목표.**
> - 브리프 형식은 기존 41장 계보(`kiddy_voice/*-claudecode-brief-*.md`)를 따른다: §0 전제 → §1 구현 → §2 검증 → §3 카피 → §4 보고 양식.
> - 🔐 **§0에 「권한 등급」 칸을 반드시 넣는다** (2026-08-05 신설, 오너 확정). 서버 엔드포인트가 하나라도 생기거나 바뀌면 **아래 3개 중 하나를 명시**한다. **비워두면 브리프 미완성으로 간주하고 발부하지 않는다.**
>
>   | 등급 | 코드 | 뜻 |
>   |---|---|---|
>   | 🌐 공개 | (Depends 없음) | 누구나. **열어두는 사유를 브리프에 반드시 기록** |
>   | 👤 회원 | `Depends(get_current_user)` | 로그인한 사람 |
>   | 🔑 관리자 | `Depends(require_admin)` | 우리만 |
>
>   남의 데이터를 건드릴 수 있는 경로면 **인가(소유권) 검증**까지 적는다 — 기존 패턴 `get_owned_profile(profile_id, user["user_id"])` 를 그대로 쓸 것. 판정 기준·근거는 [GD-S0 전수 판정표](기능별/GD-S_보안축/GD-S0_전수판정표.md).
