# 백엔드(FastAPI) 규칙

> 이 파일은 `server/` 의 파이썬 파일을 열 때만 로드된다. 루트 `CLAUDE.md` 를 대체하지 않는다.
> ⚠️ `/compact` 후에는 자동 재주입되지 않는다 — 서버 파일을 다시 열면 돌아온다.

## 🔴 `except Exception` 이 `HTTPException` 을 삼킨다 (2026-08-06 차단시험으로 실증)

401·404·429 가 조용히 '성공'으로 둔갑한다. **에러도 안 나고 화면도 멀쩡하다.**

`HTTPException` 도 `Exception` 의 하위다. 실패를 `{ ok: False }` 로 감싸는 라우터(`diary_image.py` 계열)에서
**인증·인가·한도 검사를 `try` 안에 두면** 429 가 `{ok:false}` 로 바뀌어 나간다.

- **규칙: 검사(`Depends` 외의 소유권·한도 확인)는 `try` 바깥에 둔다.**
- 부득이 안에 둬야 하면 `except HTTPException: raise` 를 **일반 `except` 보다 먼저** (`db.py`·`analyze.py:analyze_deep` 패턴).
- 검증할 때 **상태코드만 보지 말고 응답 본문에 `ok` 키가 섞이지 않았는지**까지 확인.

## 핵심 주의사항

- Railway 재시작 시 JSON 초기화됨 → `main.py` 의 `ensure_data_files()` 로 해결
- JSON 읽기/쓰기 시 반드시 `encoding="utf-8"` 명시
- Anthropic 은 반드시 `AsyncAnthropic` (sync 쓰면 블로킹)
- API 엔드포인트 주소 동일하게 유지 → 프론트 수정 불필요
- **라우터 추가 시 반드시 `main.py` 에 import + `include_router` 등록** — 누락 시 404 (chat 라우터 누락 사고)
- **응답 JSON 에 필드 추가 시 키 충돌 주의** — 프론트가 `{ ...video, ...safety }` 로 spread 하므로 같은 키가 있으면 **원본을 덮어쓴다** (videoId 덮어쓰기 사고)
- **외부 API 응답 dict 접근은 반드시 `.get()`** — JS 는 undefined 로 넘어가지만 Python 은 KeyError 로 500 (`item["id"]["videoId"]` → `item.get("id", {}).get("videoId")`)
- **Pydantic Optional 필드는 `Optional[str]` 로 선언** — 프론트가 `null` 을 보내면 `str` 타입은 422 (chat profileName/profileAge 사고)

## 🔬 백엔드는 안전망이 없다 — 검증 스크립트를 남길 것

프론트 테스트 29파일 224개 / **백엔드 자동 테스트 0개**. 프론트 실수는 테스트가 잡았지만 **백엔드에서 같은 실수를 하면 아무도 모른다.**
→ **백엔드 작업은 검증 스크립트를 레포에 남긴다.** `server/_verify_*.py` 로 만들고 `_verify_all.py` 의 `CHECKS` 에 등록하면 커밋 훅이 자동으로 돌린다.

현재 6종: 인증 기준선 · 인가(소유권) · 🐤 윤리선 카나리아 · 💸 비용 상한 · 🚨 위기 사전 · 가짜 주입 도구 자체 점검

## ⚠️ LLM 사용 원칙 — 사실은 코드가, 분위기만 LLM이 (사고: 키디 스케줄 인사)

**사실(시간·제목·수치·일정)이 필요한 자리에 LLM 자유생성 금지.** 사실은 코드로 렌더, LLM 은 톤 한 문장만.

> 사고: 부모 메모 "도복 세탁 완료" → "도복이 준비되어 있으니 편하실 것", 식단 "저녁 카레" → "함께 즐기시면 좋겠다"로 **추천으로 왜곡**. 신뢰가 생명인 안내 기능에서 치명적.

1. **부모 내부 메모·민감 텍스트는 프롬프트에 넣지 말 것** — 재해석되어 없던 내용을 지어낸다.
2. **분위기 파악에 필요한 최소 재료만**(개수·제목) 주고 "그대로 옮기거나 지어내지 말 것" 명시.
3. 한국어는 **`max_tokens` 넉넉히**(100이면 2~3문장에서 잘림), **`temperature` 는 낮게**.
4. 화면이 이미 정확히 보여주는 정보를 LLM 이 또 풀어쓰게 하지 말 것(중복+왜곡).

## ⚠️ LLM 반응에는 답의 '틀(시제·의미)'을 못박을 것 (사고: 볼 것 "동화 봤구나")

**'한 일(과거)'인지 '보고 싶은 것(미래)'인지 LLM 은 문맥만으로 헷갈린다.**
(사고: 볼 것 답 '동화'에 **"동화 봤구나"** 로 반응 — calm 예시가 과거형뿐이라 시제가 오염됨)

1. 질문 유형별 **시제/틀을 프롬프트에 명시** (`checkins.py` 의 `FRAME_HINT` — 한 일=과거 "~했구나" / 볼 것=미래 "~보고 싶구나", "절대 '봤다'로 말하지 마").
2. **few-shot 예시도 유형별로 분리** — 한 예시를 모든 유형에 재사용하면 시제가 오염된다.
3. 로컬 폴백이 항상 정확하면(`WATCH_REACTION`) 의심 시 **LLM 대신 폴백**을 쓰는 서버 안전망도 고려.
