# 🔬 정밀검수 — "다시 검증해봐"의 정식 절차

> **언제 연다:** 오너가 *"정밀검수"* · *"다시 한번 검증해봐"* · *"꼼꼼하게 다시"* 라고 할 때.
> 그리고 **스스로 "다 끝났다"고 말하기 전에도** 한 번.
> 신설: 2026-08-11 (오너 지시 — *"방금 검수했던 프로세스를 정밀검수로 하자"*)

## 이게 일반 검증과 뭐가 다른가

| | 묻는 것 |
|---|---|
| **일반 검증**(고정 축 4개) | 내가 만든 것이 **의도대로 도는가** |
| **정밀검수** | 내가 **안 던진 질문**이 무엇인가 |

🔴 **그래서 같은 검사를 다시 돌리는 건 정밀검수가 아니다.** 이미 초록불인 것을 또 보는 것은 0의 정보다.
반드시 **아직 안 쓴 각도**를 골라야 한다.

> **왜 이 절차가 생겼나 (2026-08-11)** — 저장 용량 상한을 만들고 *"서버 11종 · 프론트 372건 전부 통과"* 로 보고했다.
> 오너가 *"다시 한번 꼼꼼하고 깐깐하게 보수적으로 검증 부탁해"* 라고 했고,
> **실제 버그 3건 + 검사가 헛돌던 것 6건**이 나왔다. 그중 하나는 *"부모가 정리해도 그날은 아무것도 못 올린다"* 였다.
> 전부 **차단 시험 뒤에** 나왔다 — 차단 시험이 약해서가 아니라 **묻지 않은 질문**이었기 때문이다.

---

## 1단계 — 이미 본 것을 먼저 적는다

*"이번엔 ○○를 새로 봤습니다"* 를 쓰려면 **"이미 본 것"이 명시돼야** 한다. 안 적으면 같은 것을 또 본다.

```
이미 본 축: 고정 4축 · 차단 시험 N건 · 대조군 · 카나리아
이번에 새로 볼 축: ______
```

---

## 2단계 — 각도 목록에서 **아직 안 쓴 것**을 고른다

### 🚶 사용자 동선 (2026-08-11 에 이 각도로 3건 나왔다)
> **핵심: 코드가 도는 것과 사람이 지나갈 수 있는 것은 다르다.**

| 질문 | 실제로 나온 것 |
|---|---|
| ① **정상 사용이 막히지 않나** | 한도가 이사·재푸시·연속 저장을 죽이는가 — 이사는 일기 전량을 순차 업로드한다 |
| ② 🔴 **막힌 뒤 복구가 되나** | 조건이 해소되면 **즉시** 되나? *"507 로 막힐 때마다 횟수가 소비돼, 부모가 정리해도 그날은 못 올린다"* |
| ③ **화면 전환이 온전한가** | 링크·라우팅·상태 보존 — `<a href>` 가 SPA 를 통째로 리로드했다 |
| ④ **옆 화면이 갱신되나** | 한 곳에서 바꾼 것이 다른 곳에 반영되나 — *"지웠는데 아래 책장엔 그대로"* |

### 🕐 시간
자정 넘김(KST) · 서버 재시작(메모리 카운터 소멸) · TTL 만료 · 동시 요청 · **다음 날**

### 📏 규모
0건 / 1건 / 상한 / **상한+1** / 비정상 대량(페이지 상한 도달) / 빈 문자열·null

### 🔑 권한
남의 것 / 로그아웃 / **동의 철회 뒤** / 탈퇴한 계정 / 프로필이 사라진 뒤

### 💸 돈
이 경로가 태우는 것을 **전부** 센다 — 토큰만이 아니다. **저장·전송·DB 도 돈이다**
(2026-08-11: `[K]` 검사가 *"돈 = LLM 호출"* 로 정의해 Storage 업로드를 못 봤다)

### ↩️ 되돌리기
중간에 실패하면 **무엇이 남나**를 단계별 표로. 기능이 도는 순서와 안전한 순서는 다르다

### 🧒 아이 눈
글을 못 읽어도 알 수 있나 / 실패가 **아이 탓**으로 들리나 / **조용히 막히지 않나**

### 🔍 검사 자신 → **3단계**

## 3단계 — 🔴 검사 자신을 의심한다

> 2026-08-11 에 **여섯 번** 걸렸다. 전부 *"통과가 났다 → 배선부터 의심하라"*(가짜 주입 3원칙 ③).

| # | 물을 것 | 실제 사고 |
|---|---|---|
| 1 | 차단 시험이 **"못 잡음"** 이면? | 🔴 **방어보다 주입을 먼저 의심한다.** 주입이 세 번 연속 엉뚱한 함수에 들어가 *"못 잡음"* 이 **세 번 다 거짓**이었다 (`sb_upsert(` 가 파일에 3곳) |
| 2 | 주입 지점을 어떻게 잡나 | 함수명·줄번호 ❌ → **그 자리에만 있는 문자열**(표 이름 `"diary_assets"` 같은 것) ✅ |
| 3 | 가짜가 **필터를 적용하나** | 무시하면 *"남의 것이 안 섞인다"* 검사가 **아무것도 안 한다** (이틀 연속 당함) |
| 4 | 가짜가 **덮어야 할 이름을 전부 덮나** | `FakeDB` 가 `sb_upsert` 를 안 덮어 그 한 줄만 진짜 DB 로 나갔다 → **원본 모듈과 전수 대조** |
| 5 | 검사 **헬퍼가 측정 대상을 지우지 않나** | `upload()` 가 매 호출마다 카운터를 리셋해 3회를 1회로 읽었다 |
| 6 | **집계 함수가 감추지 않나** | `peek` 이 `min(아이별, 계정)` 이라 계정 쪽 누락이 안 보였다 → **원자값을 직접 읽는다** |
| 7 | 검사가 **막는다고 적은 것을 정말 막나** | 카나리아 주석이 *"select 를 `*` 로 바꾸면 샌다"* 였는데 실제로는 못 잡았다(응답을 키 5개로 조립하니 샐 수 없는 경로) → **주석도 차단 시험으로 검증한다** |
| 8 | **대조군이 양쪽에 있나** | 막힌다 ∧ **안 막힌다**. 한쪽만 있으면 방어가 한 방향으로만 밀린다 |

---

## 4단계 — 보고

1. **"이번엔 ○○를 새로 봤습니다"** 를 반드시 명시. 없으면 정밀검수를 안 한 것이다.
2. 찾은 것은 **근거 파일:줄**과 함께. *"그럴 수 있다"* 가 아니라 *"이 줄이 이렇게 한다"*.
3. 🔴 **방어하지 않는다.** *"이미 다 봤습니다"* 금지 — 그 말을 들은 순간 **아직 안 본 게 있다고 가정.**
4. 정말 없으면 정직하게 — *"더 볼 축이 없다, 이유는 X"*. **억지로 만들지 않는다.**
5. 고쳤으면 **검사로 못박고 차단 시험까지** — 안 그러면 다음에 또 풀린다.

---

## ⚠️ 이 문서가 못 하는 것

이건 **사고 절차**라 장치로 강제할 수 없다. 슬래시 커맨드(`/정밀검수`)로 자동 로드되게 해두었지만,
**"새 각도를 진짜로 골랐는가"** 는 아무도 검사할 수 없다.

⇒ 그래서 위 각도 목록을 **계속 늘린다.** 정밀검수에서 뭔가 나오면 **그 각도를 여기 추가**할 것.
목록이 자산이고, 빈 칸이 다음 사고다.
