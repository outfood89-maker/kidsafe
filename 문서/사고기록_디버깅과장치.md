> **왜 옮겼나:** `CLAUDE.md` 는 **매 세션 통째로 로드**되고, 공식 권장은 **200줄 미만**이다

> 이 파일은 자동 로드되지 않는다 — 디버깅에 막혔을 때 열어보라고 만든 문서다.

## 1. 디버깅 — 환경 탓으로 넘기기 전에 `git stash` (실사고: 2026-08-05)

**내 변경 직후 깨졌다면 그게 가장 강한 증거다.** 그런데 실패 개수가 흔들리면(46→7→46) 환경을 의심하게 되고, 실제로 그렇게 두 번 헛짚었다.

| 헛짚음 | 실제 |
|---|---|
| "Steam 이 CPU 146% 주범" | `ps aux` 의 `%CPU` 는 **프로세스 생애 평균**이지 현재값이 아니다 |
| "게임 부하 때문" | **게임이 켜진 채로** 기준선 199개 전부 통과(7.32s) |

### 절차

1. **오류 종류부터 본다** — `AssertionError`(로직)인가 `timed out`(느려짐)인가.
   **전부 타임아웃이면 로직이 아니라 무게 문제다.**

2. **`git stash` 로 내 변경만 치우고 같은 조건에서 기준선을 잰다.**
   5분이면 되고, 유일하게 확실한 판별법이다. **가장 확실한 검증을 가장 늦게 하지 말 것.**
   - 일부만 치우려면 `git stash push -m "메모" -- client/`
   - **치우기 전에 변경 파일을 스크래치패드에 복사**해두면 pop 실패 위험이 0이 된다
   - 🔴 **2026-08-06 실증:** 프론트 31개 실패 → 내 변경을 치우자 **36개로 더 늘었다.** 코드가 원인이 아님이 즉시 판명

3. **전부 타임아웃이면 `--no-file-parallelism` 으로 갈라라.**
   vitest 는 워커를 코어 수만큼 띄운다. **머신이 바쁘면 워커끼리 굶어 5초 타임아웃**이 무더기로 난다 — 코드는 멀쩡한데.

   | 조건 | 결과 |
   |---|---|
   | 병렬 (게임 44% + `kernel_task` 40% 물린 상태) | 31개 실패 · `import` **183초** |
   | **순차 (`--no-file-parallelism`)** | **214개 전부 통과** · `import` **7.6초** |
   | 병렬 (load 16.57 · 게임 204% · 스왑 3.3GB) | 51개 실패 · **234초** |
   | **순차 (같은 조건)** | **224개 전부 통과** · 164초 (2026-08-07) |

   ⚠️ `kernel_task` 가 높으면 **발열로 CPU 를 강제로 늦추는 중**이다. 이때 병렬 측정값은 아무 의미가 없다.
   🔒 pre-commit 훅은 타임아웃을 감지하면 **자동으로 순차 재시도**한다. 그래도 실패하면 진짜 실패다 —
   단, 부하가 극심하면(load 16+) 순차에서도 타임아웃이 날 수 있으니 **개별 파일 단독 실행**으로 한 번 더 가른다.

4. 용의자를 **반으로 자른다** (테스트 제외 / 컴포넌트 제외)
5. 로그에서 **어느 단계가 느린지** 본다 (`transform` / `import` / `tests`)
6. 원인을 단정하기 전에 **"내가 이걸 어떻게 알았지?"** 를 확인한다. 근거가 약하면 "아마"라고 말한다

### 🔴 원인을 CPU 로 단정하지 말 것 — 사흘 연속 '게임 때문'이라 했고 전부 틀렸다

| 잘못 본 것 | 실제 |
|---|---|
| `top` 의 `%CPU` 합이 178% → "CPU 포화" | **코어 1개 = 100% 기준**이다. 10코어면 최대 1000%. 실제 사용률 **32%**(대기 68%) |
| "게임이 자원을 먹는다" | 게임 RSS **198MB**. 진짜는 **Chrome 28프로세스(2.3GB) + Claude 16프로세스(1.5GB)** |
| — | **가동 9일 15시간** → 압축 5.7GB + **스왑 2GB**. 16GB 기계에 25GB어치 요구 |

**순서대로 볼 것 (2초씩):**
```sh
uptime                    # load 가 코어 수보다 낮으면 CPU 는 무죄
sysctl vm.swapusage       # used 가 잡히면 메모리가 범인
vm_stat | grep compressor # 압축이 크면 이미 쥐어짜는 중
ps -A -o rss,comm | sort -rn | head   # 누가 먹는지 (앱 이름 말고 RSS 로)
```

**CPU 대기율이 높은데 느리면 CPU 가 아니다.** vitest 워커는 각자 jsdom 을 띄워 **메모리 압박의 첫 희생자**가 된다 —
그래서 순차는 통과하고 병렬만 죽는다. 근본 해결은 **재부팅**(9일 넘게 켜뒀으면 특히).

## 2. pre-commit 훅 — 규칙을 '장치'로 (2026-08-05 신설)

### 설치는 자동이다. 손댈 것 없음

`client` 에서 `npm install` 하면 `postinstall` → `scripts/setup-hooks.mjs` 가 훅을 활성화한다.
새 기기 세팅은 반드시 `npm install` 을 거치므로 **잊을 수가 없다.**

> ⚠️ **왜 자동이어야 했나:** 훅은 `.git/hooks` 에 살아서 **git 으로 전파되지 않는다.**
> 새 기기에서는 훅 없이 커밋이 **아무 경고 없이** 그냥 된다.
> `CLAUDE.md` 에 "설치하세요"라고 적어두는 건 **'규칙'이지 '장치'가 아니다**(읽고 기억해서 실행해야 함).
> 안전장치: git 저장소가 아니거나 훅 파일이 없어도 **`npm install` 을 절대 실패시키지 않는다.**

수동으로 켜야 할 때(드묾): `git config core.hooksPath scripts/hooks`

### 무엇을 검사하나 — 바뀐 영역만

| 바뀐 영역 | 검사 | 시간 |
|---|---|---|
| 문서·설정만 | 건너뜀 | ~0.4초 |
| `server/**.py` | `_verify_all.py` — 6종 | ~10초 |
| `client/src/**` | 배럴 import 차단 + `vitest run` + `npm run build` | ~8초 |

**백엔드 검사 6종** (손으로 보려면 `cd server && ./venv/bin/python _verify_all.py`)

| # | 검사 | 막는 것 |
|---|---|---|
| 1 | 서버 임포트 | 문법 오류·순환 import |
| 2 | 🔴 **인증 기준선** | 미인증이 `GET /` 하나를 넘으면 차단. 새 라우트에 `Depends` 를 빠뜨리는 실수 |
| 3 | 🔴 **인가(소유권)** `_verify_authz.py` | *"자물쇠는 달렸는데 남의 집 문이 열리는"* 경우 |
| 4 | 🐤 **윤리선 카나리아** `_verify_canary.py` | 아이의 비공유 이야기가 부모 화면으로 새는 것 |
| 5 | 💸 **비용 상한** `_verify_quota.py` | 한도가 조용히 사라지는 것 + 계정 1개의 하루 최대 지출액을 매번 출력 |
| 6 | 🚨 **위기 사전** `_verify_lexicon.py` | 정탐/오탐/서버↔클라 사전 동일성/탐지→응답→부모신호 정합 |

- 새 엔드포인트를 **공개로 두어야 한다면**: 사유를 GD-S0 §2 에 기록하고 훅의 허용 목록을 갱신할 것(그냥 우회 금지)
- 긴급 우회: `git commit --no-verify` — ⚠️ 단 **커밋 게이트상 검증 안 된 코드의 푸시는 여전히 금지**

## 3. 문서 검색 — "없다"고 단정하기 전에 (실사고: 2026-08-01 설계 v2 오분류)

윈도우↔맥을 오간 레포라 **파일명 검색이 두 겹으로 거짓말한다.**

1. **한글 NFC/NFD** — 맥은 NFD 저장이라 `find -name "한글*"`·`grep` 이 **있는 파일을 못 찾는다.**
   → `python3` + `unicodedata.normalize('NFC', ...)`
2. **윈도우 8.3 단축명 + 대문자 `.MD`** — `kiddy_voice/` 의 4개(`KI009F~1` `KI7A19~1` `그림일기/KI366E~1` `그림일기/KI7155~1`)는
   한글로 못 찾고 `--include="*.md"` 필터에서도 빠진다.
   그중 `그림일기/KI7155~1.MD` = **그림일기 설계 v2(SoT)** — AD 브리프·`ROADMAP-고도화.md` 가 verbatim 참조하는 현행 문서.

**판정 규칙:** 못 찾으면 → `*~1*.MD` 4개 내용 확인 → `git log --all --diff-filter=D` 확인 → **그 뒤에야** "없다"고 말할 것.

## 4. 팀장이 틀렸던 것들 — 패턴 모음

같은 구조의 실수가 반복된다. 개별 사건이 아니라 **패턴**으로 볼 것.

| 패턴 | 사례 |
|---|---|
| **이미 있는 것을 없다고 함** | "그림일기 한도는 정한 적 없다" → 프론트에 이미 있었음(`REGEN_MAX=2`) |
| **콜드 스타트 값을 정상값으로 보고** | "훅이 3.2→19.5초" → 실제 2.77→3.39초 |
| **잘린 데이터를 전체로 착각** | "캐시 적중률 40.8%" → 실제 **97.2%** (Supabase 기본 1,000건 제한) |
| **입력을 반대로 넣고 결론** | 리포트↔코치 `max_tokens` 를 뒤바꿔 비용 비교 |
| **조건부 이득을 무조건으로 보고** | "프롬프트 캐싱하면 1회 2.5원" → 캐시 히트할 때만. 손익분기 하루 576회 |
| **불가능한 걸 가능하다고** | "TTS 캐싱 84% 절감" → 대화 응답은 LLM 생성이라 캐싱 불가. 실제 30~40% |
| **환경을 원인으로 단정** | 게임 탓 3회, 전부 틀림 |
| **방어는 고쳤는데 판정을 안 봄** | GD-A3 — 되읽기는 고쳤으나 사전에 칸이 없었음 |

**공통점:** 전부 **"확인하면 2분이면 알 수 있는 것"** 을 확인하지 않고 말했다.
